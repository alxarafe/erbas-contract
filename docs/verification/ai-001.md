## Coverage

Synthetic AI tests verify closed success shape and successful READ provenance,
authentication -> permission -> module -> validation precedence, effective
READ-only tool filtering, module disable/restore, AI-only authorization without
business permissions, temporary unavailability, permanent execution failure,
tool failure, per-tool re-evaluation, and safe public error envelopes.

The shared AI requests additionally cover malformed JSON, missing/null/empty/
whitespace/wrong-type/over-limit/NUL/unpaired-surrogate messages, extra
properties, caller-supplied invocation ID and security context, the exact
4000-scalar limit, direct answer with empty tools, one and multiple tools,
generated and distinct IDs, no visible tools while WMS is disabled, and restored
tool visibility.

Runner mutation tests reject empty/duplicate AI invention IDs, caller/cross-user
subject injection, extra fields, empty/wrong/write/unauthorized tool entries,
tool input leakage, wrong tool order, ignored permission or module gates, and
gate-before-authentication or gate-before-validation defects.

## Limitations

- Shared AI success scenarios require a backend-owned deterministic conformance
  assistant/model adapter for the specified messages. No live external LLM service,
  provider key, quota or internet access is used or required.
- Model quality, prompt safety, real tool-selection accuracy, provider timeout and
  rate-limit behavior, trusted runtime context propagation, actual audit
  persistence and production logging redaction are backend integration concerns.
- Live conformance requires AVAILABLE enabled `erbas.ai`, administrator permission
  `ai.assistant.invoke`, enabled `erbas.wms`, and the existing disposable CORE/WMS
  catalogue prerequisites.
- No backend/client v0.10.0 or v0.11.0 adoption is claimed. v0.11.0 is not
  published and has no tag.
