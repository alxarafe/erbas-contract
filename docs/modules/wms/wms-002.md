## Exact fields

The output is a closed object with exactly `id`, `code`, `name`. POST accepts a
closed object with exactly required `code` and `name`. Property names are case
sensitive. Additional or duplicate properties, nulls, wrong types, non-object
roots and malformed JSON return 400 after authentication, authorization and gating.

`id` is a server-generated, non-nil UUID in canonical lowercase; the UUID version
is unspecified and consumers treat it as opaque. `WmsEntityId` extracts the same
UUID schema previously inline in UoM, without changing observable UoM behavior.

`code` matches `^[A-Z][A-Z0-9_]{0,29}$`: 1–30 ASCII characters, first `A-Z`, then
`A-Z`, digits or underscore. No trim, uppercase conversion or other normalization
is allowed. Exact codes are unique throughout this catalogue. `A`, `COLD`,
`COLD_CHAIN`, `ZONE2`, `A_1` and `IS_FOOD` are valid. Numeric initial characters,
lowercase, mixed case, hyphens, spaces and 31-character codes are invalid.

For `name`, remove every consecutive U+0020 SPACE, U+0009 TAB, U+000A LF and
U+000D CR at each boundary. Do not remove any other Unicode space. After that
normalization, require 1–255 Unicode scalar values; NUL and unpaired surrogates
are invalid. Preserve case, internal whitespace and all other valid Unicode
characters exactly. `"\tCold storage\r\n"` becomes `"Cold storage"`;
`"Cold   storage"` stays unchanged; empty or ASCII-whitespace-only text is invalid.
Boundary NBSP and EM SPACE are preserved. Padding does not count toward the
255-scalar limit. Therefore `WmsStorageAttributeNameInput` has no raw maxLength;
`WmsStorageAttributeName` describes normalized output. No framework `trim()` or
UTF-8 byte/UTF-16 unit count is prescribed.

## HTTP, representation and errors

Only `POST /api/wms/storage-attributes` and `GET /api/wms/storage-attributes`
are added. POST accepts no query parameters. Success is 201 with the persisted
closed object; creation is committed before 201 and visible in subsequent GET.
No Location header is required, since there is no individual GET. An exact code
duplicate returns 409 without modifying the original or creating a second row.
Conformance tests observe that outcome without prescribing concurrency mechanics.

GET follows [COLLECTIONS-001](../../common/collections.md), identically to UoM: only optional
`offset` and `limit`, each at most once; decimal base-10 integer text, no empty,
whitespace, fractional or exponent values. Defaults are offset 0 and limit 50;
offset must be nonnegative and limit 1–100. Unknown or repeated keys return 400.
Sort by ordinal code ASC before slicing. No filters, search, configurable sorting
or cursor. The closed response is:

```json
{"items":[],"offset":0,"limit":50,"total":0,"order":[{"field":"code","direction":"asc"}]}
```

`total` counts all rows before slicing. Offset at or beyond total returns 200
with empty items and complete metadata.

| Status | Exact error body |
| --- | --- |
| 400 | `{"code":"invalid_request","errors":[{"code":"invalid_request"}]}` |
| 401 | `{"code":"unauthorized","errors":[{"code":"unauthorized"}]}` |
| 403 | `{"code":"forbidden","errors":[{"code":"forbidden"}]}` |
| 409 | `{"code":"wms_storage_attribute_code_conflict","errors":[{"code":"wms_storage_attribute_code_conflict"}]}` |
| 503 | `{"code":"module_disabled","errors":[{"code":"module_disabled"}]}` |

All responses use `Content-Type: application/json` and `Cache-Control: no-store`.
Only 401 includes `WWW-Authenticate: Bearer`; all other statuses omit it.
503 omits Retry-After. No redirects, human error text or internal details are
introduced. The current error envelope follows [API conventions](../../common/api-conventions.md).

## Security, dynamic gating and i18n

Both operations require bearer authentication and administrator authorization,
and belong to the existing `erbas.wms` module. Precedence is authentication,
administrator authorization, dynamic module gate, request validation, operation.
An invalid request therefore returns 401 anonymously, 403 for a non-admin, 503
for an admin with WMS disabled, and 400 for an admin with WMS enabled.

CORE `PATCH /api/modules/erbas.wms` disables both operations immediately.
Re-enabling allows them without restart; previously created data remains visible.
There is no new module or fine-grained RBAC.

Accept-Language never changes codes, UUIDs, property names, persisted names or
technical error codes. `name` is user content and is never translated. Bruno
compares the entire persisted collection under Spanish Accept-Language and
checks the same exact duplicate error under English and Spanish.

## Java/.NET portability review

Both supported stacks already implement the v0.6.0 UoM observable foundation:
admin policy, WMS runtime gate, persisted unique codes, UUIDs and ordered windows.
The new catalogue needs the same behavior with a different code grammar and
`name` field. Neither framework's defaults should define the wire contract.

Java can count code points while explicitly rejecting surrogate code points;
.NET can enumerate Unicode scalar values while rejecting invalid UTF-16 before
replacement. Both can remove the four specified boundary characters explicitly,
retain all other spaces, reject duplicate JSON properties at the HTTP boundary,
and enforce exact code uniqueness using their own persistence facilities. Both
can order these ASCII codes ordinally before slicing without relying on database
locale defaults. Their mechanisms and migrations remain backend-owned.

The chosen semantics have equivalent security and testability across stacks,
reuse existing policies and need no shared runtime constants package. No backend
implementation, native test or live service was inspected or executed in this task.
