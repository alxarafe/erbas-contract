# ERBAS Contract v0.5.0

**Published immutable ERBAS Contract release.** The annotated `v0.5.0` tag
resolves to `35be07fe002c364f758ae50419d0ecb86d1f0c43`, the exact validated `main`
commit resulting from the CONTRACT-004 preparation merge. v0.4.0 remains the
previous published release and the first formal release. See
[versioning](../versioning.md) for the release identity and consumption policy.

This is a compatible additive MINOR release incorporating CONTRACT-003 and
CONTRACT-003A. Health, AUTH-001, USERS-001 and existing COLLECTIONS-001 behavior,
including closed User/UserCollection models, remain unchanged.

- **Module administration:** CORE, administrator-only `GET /api/modules` lists
  currently AVAILABLE modules; `PATCH /api/modules/{id}` sets persistent enabled
  state. Authentication and administrator authorization precede validation,
  lookup and transitions. CORE administration remains accessible when all modules
  are disabled.
- **Public models:** closed Module has exactly `id`, `moduleApiVersion`,
  `dependencies` and `enabled`. ModuleCollection applies COLLECTIONS-001's closed
  envelope and fixed id ASC pagination. UpdateModuleRequest accepts only the
  required boolean `enabled`.
- **Transitions:** enable/disable is immediate and idempotent, with no restart
  or data removal. Unavailable IDs return `404 module_not_found`; transitions
  violating dependency invariants return atomic `409 module_dependency_conflict`,
  without automatic enable/disable cascades.
- **Canonical conformance modules:** `erbas.dev.math` has no dependencies;
  `erbas.dev.statistics` depends exactly on Math. These replace configurable
  module fixture IDs and serve development/conformance, not production business
  functionality. They are not mandatory in production and must not be registered
  there by default. No development-only field is added to Module.

The sole Bruno collection has **130 requests and 506 named checks** for the
two-module synthetic fixture; additional descriptor-discovery pages repeat their
checks. Docker repository verification validates OpenAPI and **96 synthetic/unit
tests**. It does not establish live backend conformance. Live conformance needs
an explicitly supplied URL, enabled administrator credentials and both canonical
modules AVAILABLE in an isolated disposable environment: the suite mutates users
and module enabled states. See [usage](../usage.md) and [modules](../modules.md).

Consumers may now adopt v0.5.0 through separately approved adaptation tasks.
Java and .NET still pin v0.4.0; no v0.5.0 backend conformance or Angular
module-administration adoption is claimed.

External plugin loading, installation/uninstallation/purge, module configuration,
functional Math/Statistics endpoints, module health/operational state, capability
or event buses, RBAC, filtering/search/custom ordering and additional module CRUD
operations are outside this release. No backend implementation internals are
prescribed. The published tag does not authorize GitHub Release, package
publication or deployment; those operations require separate approval.
