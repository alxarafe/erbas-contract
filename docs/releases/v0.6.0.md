# ERBAS Contract v0.6.0 — preparation

**Unpublished draft. No tag, release or consumer adoption exists for this revision.**
The current immutable published release remains v0.5.0 at
`35be07fe002c364f758ae50419d0ecb86d1f0c43`.

This compatible additive MINOR increment introduces WMS-001, the first business
vertical: administrator-only creation and paged listing of units of measure via
`POST /api/wms/uoms` and `GET /api/wms/uoms`. The business module ID is `erbas.wms`,
with no module dependencies. Functional gating follows authentication and admin
authorization; module administration remains CORE.

The closed UoM shape contains id, code and description. Codes are exact uppercase
ASCII mnemonics matching `^[A-Z][A-Z0-9]{0,9}$`, without trimming or uppercasing.
Descriptions are required strings, trimmed at boundaries before validation and
persistence, containing 1–255 Unicode scalar values after trimming. Whitespace
means ASCII space/tab/CR/LF; empty/whitespace-only input is invalid. Responses
contain the normalized user text, preserving internal whitespace and case.
Server-generated UUID versions are unspecified. Duplicate codes return
409 with `wms_uom_code_conflict`, without altering persisted state. Error bodies
are closed technical codes, with no general Problem Details migration.

Health, AUTH-001, USERS-001, COLLECTIONS-001, CONTRACT-003 and CONTRACT-003A retain
their existing operations, schemas, headers, statuses and security. All 130 old
request definitions and 506 named checks remain. The sole collection adds 52
WMS requests / 208 inherited checks: **182 definitions / 714 named checks** for
the standard synthetic fixture. Full conformance now additionally requires
enabled AVAILABLE WMS and an initially empty disposable UoM catalogue.

No Item, family, warehouse, stock, HU, storage engine, AI, backend implementation,
new tooling dependency or publication is included. See [WMS-001](../wms-001.md)
for the laboratory audit, alternatives, normative details and portability review.
Publish only through the existing separately authorized
[release procedure](../versioning.md#ci-and-publication-procedure).
