# ERBAS Contract v0.4.0

First executable ERBAS Contract release: one implementation-neutral HTTP API,
specified by OpenAPI 3.1 and checked by the sole shared Bruno conformance suite.
This preparation preserves the behavior already validated by both supported
backend stacks. See [versioning](../versioning.md) for publication status and
the separately authorized tag/publication procedure.

- **Health:** public `GET /health` establishes HTTP process liveness, independent
  of database or dependency health.
- **AUTH-001:** email/password login, closed responses and generic errors;
  implementation-neutral opaque bearer tokens used against the issuing backend.
- **USERS-001:** current identity and administrator-only user list, get, create
  and enabled/admin updates; disabled-account rejection and last-admin protection.
- **COLLECTIONS-001:** deterministic paged user collections with stable id ASC
  order and the closed `items`, `offset`, `limit`, `total`, `order` envelope.

The shared suite contains 82 requests and 313 named checks. Repository
verification uses Docker and validates OpenAPI plus 69 synthetic/unit tests;
live-service conformance requires an explicitly supplied URL, an enabled
administrator and a disposable environment because tests mutate users.

Registration, password/email changes or reset, refresh/logout, MFA, granular
roles/permissions, module APIs, custom ordering/filtering/search and cursor
pagination are outside this release. Token format and cross-backend token
acceptance are not standardized. Demo defaults are a development convention,
not HTTP contract behavior. No backend implementation internals are prescribed.
