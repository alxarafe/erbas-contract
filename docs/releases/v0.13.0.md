# v0.13.0 local candidate

CRUD-CONTRACT-001 prepares an additive MINOR over immutable v0.12.0. It adds the
[Generic Resource Runtime protocol](../core/resources-001.md), separate generic
page and metadata/presentation/action schemas, explicit typed filter operators
and shared conformance. Existing public route schemas, error envelope and legacy
collection semantics remain unchanged. Generic-route evaluation precedence has
an explicitly approved, strictly scoped exception; it is not a new global rule.

This is not published, tagged or adopted as a backend pin. .NET remains pinned
to v0.12.0 and validates this candidate only through explicit development opt-in.
No new Java or client adoption is claimed. Historical v0.12.0 preparation reports
retain their original wording. No release/tag/publication is authorized here.

Verification completed:

- `./bin/check-fast` and `./bin/check-scope resources` passed. Authoritative
  `./bin/check` passed 213 tests, zero failures/skips, including full synthetic
  conformance and deliberate operator/conflict/total faults. The sole collection
  contains 611 physical requests / 2,639 named checks; metadata iteration may
  execute a request more than once on deployments with more resources.
- Existing published-schema preservation checks passed without changing their
  historical hashes. The first comparison omitted removal of the three newly
  bundled Resource parameters from its legacy view; that view was corrected.
  Direct old/new component comparison found no changes to existing definitions.
- Live .NET checks passed against published v0.12.0 and, explicitly and separately,
  this candidate on fresh disposable infrastructure. Final candidate verification
  passed 1,076 native tests, shared conformance, persistence/log-secrecy checks
  and database/container cleanup. Native evidence includes exact page omission,
  CRUD 409, typed metadata, existing Assets behavior and unchanged error paths.
- Cross-stack portability is assessed in the linked review; no Java/client
  implementation or candidate adoption is claimed. No dependency/lockfile,
  persistence or business-module changes belong to this contract task.
- Final diff, credential-marker/NUL, documentation-link and scope review passed.

The first generic client can implement static discovery, list/filter/sort/search/
pagination, create/PATCH/delete, MANY_TO_ONE lookups, optional neutral forms,
action parameters/availability/execution and common errors. It must use lossless
numeric handling and retain server-side business validation. Dynamic schema
binding, relation navigation, workflows, bulk CRUD and record concurrency remain
outside scope. Availability is advisory, not a promise of a valid state transition.
