# ERBAS Contract v0.10.0

**v0.10.0** is a compatible additive MINOR over immutable [v0.9.0](v0.9.0.md).
No consumer change or backend/client adoption or live conformance is claimed.

## Compatibility and scope

This compatible additive MINOR adds [CORE-CAP-002](../core/capabilities-002.md):
`POST /api/core/capabilities/{capabilityId}/invocations` for synchronous execution
of the three existing WMS READ capabilities. Requests contain exactly `input`;
success returns the server-generated nonempty opaque `invocationId`, exact
`capabilityId` and descriptor-conforming `output`. Existing offset/limit inputs
and collection business behavior are reused.

Authentication precedes ID validation and effective capability authorization;
body/input validation follows availability and permission checks. Unknown,
unavailable, disabled and unauthorized capabilities share the discovery masked
404. Caller security context is rejected. Trusted server-side context and minimum
attempt/result audit are specified without public context fields or an audit API.
Unexpected execution failures and known invalid output use only HTTP 500
`capability_execution_failed` in the existing global error envelope. No internal
failure distinction or invocation ID is exposed in errors.

Published discovery, registration rules, descriptor content, administrator
permission mapping, capability behavioral versions (`1.0.0`) and existing direct
HTTP operations are unchanged. Write execution and all other excluded later
capabilities remain outside scope. No dependencies, lockfiles or tooling versions
change. v0.9.0 release notes and historical verification reports remain unchanged.

## Focused verification

The single collection now contains **560 requests / 2467 named checks**:
**38 requests / 152 named checks added**. All 522 existing requests and their
assertions remain intact. New invocation scenarios compare default and structured
pagination results against existing direct GETs and test security precedence,
masked lookup, malformed input, rejected caller context and WMS disable/restore.

See [CORE-CAP-002 verification](../verification/core-cap-002.md) for the exact
Docker commands, focused results, published-contract preservation and limitations.
The full `./bin/check` passed **173/173 tests** after the final CORE-CAP-002
cleanup. Live `./bin/test URL` conformance was not run because no external
backend was part of this contract-only task. Synthetic fixtures do not establish
backend conformance, trusted runtime context propagation or actual audit
implementation.
