# ERBAS Contract v0.7.0 — draft preparation

**Unpublished local preparation; no v0.7.0 tag, release or backend conformance claim.**
Classification: **compatible additive MINOR**.

The current published immutable release is v0.6.0, tag object
`73740c956402a7405b667498507ede66fc19a66c`, target
`92d1282154f340aadcfdf93f52a82a1f3472b335`. Java and .NET adopted v0.6.0.

WMS-002 adds `POST /api/wms/storage-attributes` and
`GET /api/wms/storage-attributes` to the same `erbas.wms` module. Closed Storage
Attributes contain id, code and name. Exact uppercase ASCII codes allow
underscore and 1–30 characters; names use four-character boundary trimming and
1–255 Unicode scalar values after normalization. Names remain persisted user
content, independent of Accept-Language. Duplicate codes return an exact 409
technical error without mutation. Administrator security, dynamic module gating,
headers and COLLECTIONS-001 pagination follow WMS-001.

All v0.6.0 operations and closed schemas retain their observable behavior.
UoM semantics, Health, AUTH-001, USERS-001, COLLECTIONS-001, module administration,
canonical dev modules, existing errors and security remain unchanged. The common
UUID component is only equivalent extraction of the existing UoM UUID rules.

The sole Bruno collection retains 182 requests / 714 named checks and adds 84
requests / 336 checks: **266 requests / 1050 named checks**. Ten additional scoped
synthetic faults and structural compatibility checks validate the runner.
Full conformance additionally requires an empty disposable Storage Attribute
catalogue. Repository verification is not live Java/.NET conformance.

No ItemFamily, Item, fine-grained RBAC, exclusivity, storage rules, topology,
inventory, AI, backend or client implementation is added. See
[WMS-002](../wms-002.md) for decisions, exact semantics and portability.
Tags, push, release and deployment require separate express authorization.
